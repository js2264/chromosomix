chromosomix 0.11.0

What changed in chromosomix 0.11.0, released on 14 August 2026.

Changed

Section titled “Changed”

  • f folds the Files panel, and the track-fill overlay has no shortcut. The single-letter space was down to q and z when a fifth panel arrived, and neither is a letter anyone reaches for a list of files. Between a column — one of five, in the row of marks at the top of every window, whose four siblings are b, a, m and j — and one of eleven overlay toggles whose button is on screen beside the picture it changes, the letter belongs to the column. The fill toggle is untouched and still in the command palette; it is one keystroke that is gone.

  • Save writes the whole window, and the file is now called a workspace. The disk button in the top bar used to write the tab in front of you, which made it the third button on that row doing something a reader could reasonably have expected of the other two. It now writes every open tab in one file — each with its view, its tracks, its marks, its bookmarks, its ticked sequences, its table filters and its analysis recipes — and records which one was in front. Dropping it back opens all of them.

    The pair of buttons now states a real difference rather than two words for one thing:

    Share this session as a link — the tab you are looking at. Save this workspace as a file — every tab, with everything in it.

    A link stays one tab on purpose. The advice line already warns past about eight thousand characters and a single session with eight tracks is a few thousand, so a link carrying six tabs would open by telling the reader not to use it. What is new is that both roads carry the same format — a link is a workspace of one — so there is one parser, one version gate and no way for the two to drift apart.

    A dropped workspace is added, never substituted. Six open tabs are not closed by a drop; they were the reader’s, and there is no undo. The one place that does replace a window is the offer on the first screen after a browser restart, which has asked first. A window showing nothing but the picker gives that tab up, and a file with more tabs than the window can hold says how many it left rather than dropping them in silence.

    The file format is a clean break, and old .metacooler.json files stop opening. They are a tab where the reader now has a window, and carrying both shapes would mean two readers to keep in step for the sake of files that are a few weeks old and a re-save away from being current. Saving again from this build is the whole of the fix. The published example datasets and the CLI’s replay moved with it — replay takes a workspace and re-runs the tab that was in front, or the one --tab <n> names.

    GLOSSARY.md moved with it too. It had session file as one of the senses of session and gave the saved file to SessionConfig; there is no such thing any more, so workspace file is now its own entry and a config is what one holds. The glossary’s own rule — where it and the code disagree, the code is right and the glossary is a bug — is the reason that is part of this change rather than a follow-up.

  • On a turned map the guide becomes a vertical line while a stretch is being chosen. At rest the guide under the pointer is a pair of 45° rays, and that is the honest answer to what is this cell: a turned map’s two directions are not its two axes, so the cells sharing a place with the contact under the pointer are a ray rather than a column. It is the wrong answer the moment the next press names an interval instead — Shift held, Option held, or a form waiting to be pointed at — because then the reader is not choosing a contact, and the mark that says where an interval starts is the edge it starts on. So the rays collapse to one vertical line at the pointer’s own column, and the tracks beside the map drop back to a single hairline under it rather than marking the two anchors of a contact nobody is selecting. It answers the modifier rather than the movement, so pressing Shift over a stationary hand changes the guide immediately.

  • Windows installers are temporarily not built. The --win leg of the release workflow is commented out, so releases carry the macOS and Linux installers and no .exe. Nothing about the target changed — npx electron-builder --win still works from a clone — and the leg is left in place, commented, so restoring it is uncommenting three lines. fail-fast: false meant the other legs never depended on it, and collect attaches whatever artifacts exist. docs/desktop.md and the release body say so, and both point Windows readers at the standalone HTML page, which needs no installer anywhere.

  • A folded column leaves a tab rather than nothing. Folding one used to take it out of the layout entirely, which left the four marks up in the header as the only sign it existed — and a mark in the window furniture says neither which column is folded nor what is in it. A folded column now keeps a strip of itself with a tab standing on the bottom of it, carrying the panel’s mark, its name, the key that opens it and a chevron pointing the way it will open. The tab is turned a quarter-turn anticlockwise, so the name reads bottom-to-top up the side of the window like the spine of a book — which is what buys it the room to be named at all: a strip wide enough for “General” written upright would be a column, and what a folded column has to cost is a strip.

    They nest, and it costs no arithmetic: the four columns are already ordered outermost-first from each edge, and a folded strip sits exactly where its column would. Two folded panels on the left are two tabs side by side at the edge of the screen; open General and the Annotations tab moves out to stand against it, while General’s own tab always stands at the screen edge. The right side is the mirror — Analysis at the edge, Aesthetics against it. Nothing is measured, so no tab can be left stranded behind an expanded column. A panel with nothing to show still leaves altogether: a tab is an invitation, and one that opens an empty column is worse than the column’s absence.

  • The panel buttons come after the name in the header, and the strapline is gone. Four unlabelled marks used to open the row, so a reader identified them before reaching the thing that says what they are looking at. They are now a group set off from the title by a rule, and the line that explained the app to somebody who had already opened it has given them its room.

  • General is marked file-cog rather than a fold arrow. Its three siblings are already marked by what they hold — layers for the annotation stack, chart-spline for the picture’s controls, beaker for what can be computed — and an arrow said only “this panel folds”, which is true of all four of them. What is behind this one is the file and what can be read off it.

  • A Shift-drag now opens the stretch it named on the diagonal. The gesture names a band of one axis and zooms to it; the axis nobody dragged took the same zoom and kept whatever centre it happened to have. So the same drag over the same stretch of chromosome I landed on a different picture depending on where the view had been panned to — that stretch against a megabase somewhere else — and nothing on screen said which. What a reader dragging a band out of a contact map means is this stretch, against itself, so the other axis is now centred on the same stretch and what comes back is the on-diagonal square.

    Unchanged where the block has no diagonal to open, which is a chrI × chrII panel: there the other axis keeps its centre, since pulling it to a bin the block does not contain would only jam it against an edge.

Fixed

Section titled “Fixed”

  • A ratio drew “present here, absent there” in the colour that means the opposite. x / 0 is Infinity, and it is a real reading — the strongest statement a ratio can make in the numerator’s favour. The raster tested the pooled value with Number.isFinite and sent everything that failed to the bottom of the ramp. That is right for -Infinity, which is what 0 / x becomes on log2, and it is exactly backwards for +Infinity: the cells where the first file has contacts and the second has none were painted the second file’s colour.

    The two arms are the same size — on an E. coli pair at 5 kb, 7.7% of cells each — so half of every saturated cell in the picture carried the wrong sign, and the half that was wrong was the half worth looking at. It could only be caught at the pointer, where two adjacent cells reading 0.001 · 0 and 0 · 0.001 were the same shade of dark blue.

  • A ratio of two balanced maps was silently rescaled, and the rescale ate the finding. ratio and difference forced the depth match on and hid its tickbox, on the grounds that two libraries of different depth differ by a scalar and a ratio is that scalar everywhere. True of raw counts. Not true of balanced ones: ICE puts every bin’s marginal at 1, so two balanced matrices arrive on one normalisation with nothing left to correct — on the pair above, the two marginals agree to 0.2%.

    Matching them again was not a no-op, because matchGain does not measure depth. It measures the 99th percentile, and the 99th percentile of a Hi-C map is made entirely of near-diagonal cells — which is where two conditions differ. It returned 1.478 and shifted every cell of the ratio by −0.56 in log2, a quarter of the ±1 range such a map is drawn on: a near-diagonal band that another tool puts at +0.60 came out at +0.04, white instead of red, and the same comparison made anywhere else disagreed with the viewer. It also moved with the viewport, since the gain is measured on the block that was read — the same cell reported a different ratio at different zooms.

    Depth matching is now off by default on balanced values and on as before for raw counts, and the tickbox is offered under all three operations instead of being hidden under two of them.

  • The hover readout printed most of a balanced map as 0. fmt.num rounded to three decimal places, and a balanced cell is a fraction — at 5 kb on a bacterial genome the typical value is a few times 1e-4. Two cells three-fold apart printed the same string, so a reader checking a ratio against the counts under it was shown a pair that could not have produced it. Values below a thousandth now keep three significant digits, and below 1e-7 an exponent.

  • Two metagenomes selected together hung the tab. A file with a genome layer has no deck for a second one to join (§16.8), and the fallback for that case was written as “open it as this session’s map” but implemented by calling the dropped-file router — which had since learned to send a map back to the companion path that was calling it. The pair recursed until the stack ran out, in the one place where the fallback was meant to be the calm one. Found while giving the header’s new add button the same rule to follow.

  • A shared link carried three things it promised not to. Two comments in the codebase already stated the rule — a session’s compare field says “a shared link still cannot” carry a local second file, and the deck’s own module says spelling a companion’s name into a link “would post a private filename to a stranger, which shareLink.ts already refuses to do”. Neither was true. A link carried the local compared file, the deck’s local companions, and (once sessions began recording it) the size and modification time of the sender’s own file.

    Worse than useless to a recipient: those names are bare filenames, and opening one goes through a grant store keyed on the bare name whose guard compares only the name — so somebody who had ever granted their own rep2.cool would have opened their file in the sender’s slot, with every label on screen agreeing. The redaction now happens inside the encoder rather than at its call site, so a second caller cannot forget it, and the test asserts against the encoded payload rather than the decoded object: the point is that the name never leaves the machine, not that the far end ignores it.

    A local track is kept, and the rule that decides all of it is now written down in both places: a private name is stripped only where the structure survives without it. A dropped companion costs a label — the ~ placeholder keeps the slot, the count and the order — while a dropped track costs the row.

Added

Section titled “Added”

  • Connect a folder, and browse it in a panel — a directory on this machine, or a bucket, read the same way. Every door to a file this app had asked which file once and then closed: the picker, the header’s +, the browse button beside a URL box. That is the right shape for opening one thing and the wrong shape for the way people actually work with a directory of data, which is to open one, look, open the next, and keep going for an afternoon. Files on a bucket could only be added one at a time, and a folder on the disk could not be browsed at all.

    A Connect button now sits beside the + in the header — a plug, because what it attaches is a place rather than a file — and what it fills is a fifth side panel, Files, folded with f. Inside it: the folders you have connected, and the tree of whichever one you are in, with crumbs and a filter. Every file row loads into the tab you are in when you click it or press the → at its end, and every file row can be dragged — onto the map’s edge rectangles for a lane in that stack, onto a companion for a track on that map, onto the Tracks card, onto the page. A dragged row carries a folder and a path rather than bytes; the file behind it is fetched at the drop, once.

    A local folder and a bucket are one thing to everything above the byte layer. browse/folder.ts is the whole interface — given a path, the sub-folders and the files; given a file, how to open it — and the two backends are the entire difference between them. It is one column, one tree, one set of crumbs, and one filter, over both.

    What a local folder means depends on the browser, and the row says which you got. In Chrome, Edge and the desktop app it is a real connection: this browser keeps permission to list the folder and read what is in it — not the files themselves, and nothing is uploaded or copied — so it is still there after a reload, and it picks up a file a pipeline wrote into it five minutes ago. Firefox and Safari have no such thing; there the folder is a snapshot taken when you connect it, marked this visit on its row, gone after a reload. Offering it in two browsers and not the other two would have taken a working gesture away to avoid writing one sentence.

    A connected folder is a wider grant than a chosen file, so it is listed in About → what is stored beside the files you have allowed, disconnectable one at a time and swept by forget everything. Nothing about §11 changes: a local folder is read in place by code on your own machine, a bucket is read by your browser from the bucket, and there is no server in between because there is no server.

  • A public bucket needs nothing but its link. A bucket entry used to demand six fields, five of which are a key — so a reader with a URL out of a paper met a form that read as you need an AWS account for this. Public is now the default and it is one field; a key is behind a switch. Everything under a keyless prefix is listed and read unsigned, which is what public data always took.

    One thing to know before pointing it at a bucket: listing needs s3:ListBucket granted to everyone in the bucket policy, which is a different grant from the s3:GetObject that makes files downloadable, and most published buckets grant the second and not the first. A public bucket that refuses to be listed is an ordinary configuration rather than a fault, there is nothing an app with no backend can do about it, and the message says which of the two grants is missing and that files under the prefix still open by URL. docs/hosting.md has the policy to paste. Browsing a public prefix needs no CORS change: an unsigned listing is a simple request, so it is never preflighted, and the policy that serves public downloads already answers it.

    The dialog behind private buckets… is now just Buckets, since it lists both kinds, and its add form is the one the Connect dialog uses — one implementation, so the two cannot come to disagree about what a valid entry is.

  • correlation, a new entry in the score picker: the square replaced by the Pearson correlation between its rows. Two bins correlate when they contact the rest of the sequence in the same pattern, so the checkerboard this draws is the A/B compartments — and it is drawn through the same correlationMatrix and the same usableBins the Compartments task solves for its eigenvector, not a second implementation “for display” that would agree with the first until it did not.

    It is one entry rather than three controls, and it belongs in that list for the reason O/E is kept out of it. O/E is excluded because it composes — the standard pipeline is O/E of balanced counts, and folding it in would make balanced and O/E mutually exclusive for no reason but the control. The correlation composes with nothing: the cell no longer holds a contact at all, it holds a coefficient between −1 and 1 for a pair of bins’ whole rows, and the pipeline that produces the compartments is fixed at balanced → O/E → correlate. So the entry carries all three steps and the reader picks one thing; a control per step would be three controls with exactly one legal combination. Offered only on a file that carries weights, since a correlation of unbalanced O/E is a correlation of the coverage bias — which is per-bin, and therefore looks exactly like a compartment. The caption names every step that was applied.

    A dropped bin comes back as a gap, not as a zero. A zeroed row asserts that its bin is uncorrelated with everything, which is a strong and false claim; on a map it would be a stripe of definite colour across the checkerboard. The scope line says how many were dropped, because a blank row and a sparse corner look the same.

    It is the one cubic step in the viewer, so it runs on the analysis thread — its own client, not the drawer’s, so a correlation never queues behind somebody’s insulation pass — reports a percentage, and is cancelled by picking another score. Measured at 32 ms for 232 bins, 232 ms for 464 and 2.8 s for 929, so the map caps at 1,500 a side.

    Where it cannot be drawn — a second file open under ratio, a contig_A × contig_B block whose rows and columns are not the same bins, or a square past the cap — the map falls back to the O/E underneath it and the caption says so. That is deliberate: the O/E is a real picture and looks like one, so nothing else on screen would betray that it is not what was asked for, and the caption is the only part that survives an export.

  • A despeckle, in the smooth picker beside the transform. Each cell replaced by the mean of the cells around it with its own value left out — terra::focal with a zero centre weight, which is the filter Hi-C figures are usually made with. Off, 3 × 3, 5 × 5, 7 × 7; carried in the link, and written into the colourbar caption (counts · smoothed 3 × 3), because a smoothed map otherwise looks exactly like a map.

    Leaving the centre out is what makes it a despeckle rather than a blur: a cell that disagrees with all eight of its neighbours is evidence about the neighbourhood and not about itself, and a filter that kept a ninth of its own value would carry a wild pixel into the result at a ninth strength instead of removing it.

    It is applied per file, before two files are combined, which is what makes it useful on a ratio rather than merely cosmetic. Smoothing the ratio would have to average the Infinity and 0 that x / 0 and 0 / x produce, and one infinite cell poisons every window it falls in; smoothing the inputs makes those cells finite before the division, because a zero cell with contacts around it is no longer zero. On the E. coli pair at 5 kb it takes the saturated cells of the ratio from 15.3% to none at all at 3 × 3, while the 0.43% that are genuinely unbalanced bins stay blank.

    Two departures from the R original, both about edges. The divisor is the number of cells that contributed rather than the fixed (2r+1)² - 1, because here the boundary is the viewport and the alternative is a dark frame that moves when the map is panned; and a NaN cell keeps none, because filling it from its neighbours paints a measurement over the one place the map is saying it has none.

    Cost is flat in the radius — a separable running window rather than (2r+1)² reads per cell — so 7 × 7 is no dearer than 3 × 3.

  • A blue–white–red diverging ramp, BuWtRd. Higher contrast than RdBu_r and with more of its range spent away from the centre, which suits a sparse ratio map: most cells sit near neutral, so a ramp that stays pale through the first third of each arm spends its colour where there is least to say. Its white is anchored to the middle of the scale rather than to the fifth of its eight stops — spread evenly that would land at 4/7, and a map of two identical files would have come out faintly blue everywhere.

  • A button that adds a file to the tab you are in. Dropping a file on the page has always added rather than replaced — a second cooler comes up beside the first, a bigWig joins the tracks, a chrom.sizes answers a browser’s guessed lengths — and that is the behaviour the whole content area has taken since decks existed. What it never had was a button. Every click-sized door to a file went the other way: the file crumb, the brand, Open a different file and a new tab all replace what is open. So the commonest thing a reader wants to do with a second file was reachable only by dragging one in from a window, and the controls that looked like they would do it did the one thing that loses work.

    The header now carries it, past a divider of its own after the four panel buttons: a file with a + on it, in every view, opening the picker over what is on screen. It is the same picker the file crumb opens — the drop area that also takes a click, the URL box, the way into a private bucket — with the published catalogue left out, because every entry on that list is a whole session and offering it here would be offering to throw the tab away from the one control whose promise is that it will not. The mark is a file with a plus rather than the bare + one row below it in the tab strip, since that one adds a tab and this one adds a file to the tab you are in.

    A URL typed into it takes the routing a dropped file takes, which it could not before: a map goes into the deck beside the one that is open, anything else goes to the tracks, and a bucket-browsed file carries its own key there. On an empty tab the distinction does not exist — there is nothing to add to — so it opens instead, exactly as the landing page does, rather than taking a lone bigWig and finding no track list to put it in.

  • The picker now says which file it wants back, not just its name. A session saved from a local file names it by its bare filename, and rep1.cool is a name a reader may well have several of — so the note asking for it now carries the size and the modification date the session was made with. That is the difference between finding the right file and finding a file with the right name.

    And when a file arrives whose name matches but whose bytes do not, the app says so once and opens anyway. That is either the same file re-run through a pipeline — legitimate, and worth knowing, because the numbers on screen are then not the numbers in the figure — or somebody else’s file of the same name. The two are indistinguishable from inside the app and one of them is a thing people do on purpose, so it is a remark and never a refusal.

    Saying it needed a third way to speak. The shell had a modal, which takes the keyboard and demands an answer, and the error view, which replaces what is on screen; both are far too loud for “this opened, and here is something you may want to know”. Notes now appear as a dismissible row under the tab strip, where the restore offer already lives.

  • Closing the browser no longer ends the session — it offers it back. The tab strip has always lived in sessionStorage, which is a deliberate rule and not an oversight: a set of open files is a train of thought, it belongs to the window it was opened in, and closing the tab is meant to end it. That rule is unchanged, and sessionStorage still wins whenever it is present — a reload reads it and never looks anywhere else. What is new is an answer for the one case it cannot cover, because the storage is gone with the window: the browser was closed.

    Alongside it there is now a durable record — every tab, its file, its tracks with their colours and limits, its marks, bookmarks, ticked sequences, table filters and analysis recipes — written to IndexedDB on a debounce and flushed when the page goes away. On the first screen of a browser that was closed with work in it, a row above the picker says what was open and when, and offers to bring it back.

    Offered, never applied, and that is two decisions rather than one. Silently reopening six files a week later reverses the decision the reader made by closing them; and on a shared machine it would put somebody’s unpublished figure on screen for whoever sat down next, which is the reader §11 is written for. Start fresh is a real answer and it deletes the record rather than hiding the note, because an offer that returns tomorrow having been declined today is not an offer.

    The record holds no file contents and never will. A local file still comes back detached, exactly as it does from a reload, so this stage changes nothing about what is read or copied — §11 and §12 are untouched, and every browser gets it, not only the ones with a file-handle API.

    Two traps are worth recording, because both failed silently and both were found by driving the real application rather than by reading the code.

    A restored tab is primed — it holds a view state and has read nothing — and a config is built by reading that tab’s session memory, which after a browser restart is empty. So the first click would have gathered eight empty configs and written them over the good record. The workspace is therefore applied into memory before the first tab is primed, which is also the order applyConfig already required for its own reason.

    And a window with nothing open is two different facts. After the reader closes their last tab it means forget this; at startup it means nothing has been restored yet — and acting on the second deletes the record while the read that would have offered it back is still in flight. A race, resolving differently on a warm cache than a cold one, so the workspace disappeared on some loads and not others with nothing in the console either way. The rule is now a pure function with a test rather than three conditions in the shell.

    A third thing that had to change for any of it to be true: the record follows the workspace, not the view state. Loading a track, placing a mark and saving a bookmark are most of what a session is and none of them navigate, so a record written at the last navigation came back missing everything the reader had done since.

  • A local file you have already opened reopens itself after a reload. In Chromium and in the desktop build, dropping or choosing a file now also hands the page a FileSystemFileHandle — a capability, not a path and not a copy — and that is what is kept. A reload, a restored tab or a reopened workspace resolves the grant and reads the same file, with no drag and, while the browser session lasts, no prompt.

    Nothing about how the file is read changes: what comes back is the same File object a drop produces, read a slice at a time by the same LocalFileSource as before. No bytes are stored, nothing is uploaded and nothing is duplicated on disk, so §11 and §12 stand exactly as written. Firefox and Safari have no such grant to give, and there a local file comes back detached as it always has.

    The tracks come back too, which is the larger half of what a reload used to cost: a map is one drop and the bigWigs beside it are eight. A restored track with a grant behind it says reopening… and fills itself in, keeping its id — so it does not jump to the bottom of the card — along with its colour, its limits, its height and its edge. They resolve in parallel rather than one after another, and a grant that turns out to be spent puts the row back exactly where it used to land, with the re-open this file button that has always been the way back.

    Two things this deliberately does not do. It does not put local file names into the URL hash: this browser being able to reopen rep1.cool says nothing about anybody else’s, so the shareability test the hash is gated on is unchanged, and a link still carries only what a recipient can act on. And it does not ask for permission on the boot path, because a permission request without a user gesture resolves without ever showing a dialog — the reader is asked when they click, and never by a page that is merely loading.

    A grant is keyed by the file rather than by the tab, so two tabs on one file share it and one .mcool at five resolutions is one grant. The row also records the file’s name, size and modification time, because a local file’s URI is its bare name and two rep1.cool from two directories would otherwise collide: a name that no longer matches is refused outright rather than opened, since showing the wrong file with every label on screen agreeing is worse than asking for it again. A file that has merely changed is not refused — a re-run pipeline overwriting a file somebody is reading is a legitimate thing to do.

  • The deck and the comparison come back too, and the tracks land on the right panels. These were the two files a reload lost most quietly. A local companion is destroyed at serialisation — maps writes ~ for one — and a local second file was never in the hash at all, so neither could even be refused: by the time anything could ask, the name was gone.

  • Rectangles, in the Manual annotations card. The card drew two of the three things people put on a contact map by hand: a line says this coordinate and an arrowhead says this cell, and there was no way at all to say this block of contacts — which is the mark a domain, a corner peak and a pair of loci worth boxing all want. The workaround was four lines making a box out of crosshairs, which is four marks to move and four to delete.

    A rectangle is two intervals, one per axis, rather than an interval and a shape. That is what makes on- and off-diagonal the same mark and any ratio expressible: I:120000-180000 against itself is a domain, two short stretches a megabase apart is a corner peak, and a short stretch against a long one is a locus against a whole arm — a thing no square could have said. Typed with the second box left empty means the same stretch on both axes, the same courtesy the arrowhead form does for a cell on the diagonal.

    Drawn with a drag, which is the gesture a hand already makes for a box: press at one corner, let go at the other, with the map’s own marquee and its coordinate chips showing what is about to exist. The marquee follows the hand on both axes — a selection is squared because it resolves to one range, and a mark does not — and it snaps out to the edges of the cells the two ends are in, which is what commits. Holding Shift locks the box to the diagonal, so a domain is one gesture. The mode stays on afterwards, as the other two do, because marking up a figure is several marks — and a click while the map is waiting for a drag places nothing rather than navigating away from the picture being drawn on.

    On a turned map the box is off the diagonal if that is where it was drawn. Both ends of the drag are taken back to the square the band was rotated out of, exactly as a click is, so pressing over one contact and releasing over another names the rectangle those two contacts span — the one thing a band selection there cannot say, since a selection over a turned map is always a stretch of the genome against itself. Shift there collapses each end onto its own midpoint rather than snapping the pointer, which gives the on-diagonal square through the two places the drag ran between. And what is drawn while the hand moves is the mark itself, through the code that will draw it for good: a rectangle of rows against columns leans at 45° on a turned map and folds where it crosses the diagonal, so a rubber band would be a box drawn around a shape that is not one.

    Which gesture a form asks for is now part of what it hands the map: the two marks that name a place take clicks, the one that names an extent takes drags. A plain drag draws the box rather than panning, because a reader who has just pressed a button that says draw on map is going to drag on the map, and asking for a modifier on top of an armed mode with a lit button and a changed cursor is asking twice.

    On a turned map a box is drawn as the contacts it names rather than as its own outline, which is the same rule every other mark there follows: off the diagonal that is a parallelogram leaning at 45°, and on it that is exactly the triangle a BED domain gets, because an on-diagonal box is a domain drawn by hand. A box drawn across the diagonal has an image on each side of it; where they genuinely fall apart — a locus against a whole arm turns into two stripes leaning opposite ways — both are drawn, and where one falls inside the other, which is every box drawn near the diagonal, only the outer one is, since a second outline in there is the edge of nothing.

    Boxes are anchored in the lane stacks the way loops already were, a triangle per edge on each axis: a domain boxed on the map puts its two boundaries under the tracks, in the coordinate the tracks are drawn in, which is where the comparison is actually made. They go out with the loops as BEDPE, whose six coordinate columns are exactly a pair of intervals — the row is the box rather than a summary of it — and they are carried in a session file and in per-file session memory like every other mark.

  • chr1, 1, 01, I and NC_000001.11 are one chromosome. Two files of the same genome disagree about its names more often than they agree — UCSC writes chr1, Ensembl writes 1, a yeast cooler writes chrI and the chrom.sizes beside it writes 01 — and until now every one of those was a different sequence to this viewer. A .hic off 4DN put beside a .cool out of a local pipeline gave a blank rectangle under a bar claiming the deck was one navigation, and the only fix was to go and rewrite one of the files.

    So a deck of files that spell their chromosomes differently is now one deck, a track is renamed into the map’s vocabulary as it loads, the locus box takes whichever spelling you have in your hand, and two coolers of one assembly are no longer refused the blended square for the chr in front of one of them.

    The rule is that it never silently matches two different sequences, and everything else follows from it. length vetoes rather than persuades: two sequences of equal length are not the same sequence, so nothing is ever matched because the lengths agree, and a match whose two lengths disagree is reported rather than taken — hg19’s chrM and hg38’s chrM are one name and two sequences, two bases apart. A name whose shape is not recognised is matched by its spelling and nothing else, which is what makes this safe on a metagenome: NODE_1_length_338947_cov_15.4 is an opaque id from an independently assembled organism, and two of them agree by coincidence (§8.5).

    X is the hard one, and the list settles it. X is the tenth chromosome of S. cerevisiae and the sex chromosome of everything else, and the string cannot tell you which — so the decision is made from the whole file: one that also holds IX and XI is counting in Roman, and its X is ten; one whose numerals stop at V is C. elegans, and has no chromosome ten to confuse it with. Which is also why the reading travels: a companion panel is told how the lead counts, because a name cannot carry that and a guess would draw chromosome ten under the label X.

    Every match says which rule reached it — the chr prefix, leading zeros, Roman numerals, an organelle spelled another way, the accession — and a panel that answered a name it does not itself write prints both spellings under its heading. No remote files: the reader uses synchronous range requests, which exist in a worker and not in Node, and curl is better at the missing half than anything this could contain.   • The figures answer questions now. Log toggles per axis, a series picker (alt-click a chip to isolate it), a hover readout, a drag across the plot to zoom an x range, double-click to reset — and, for a pileup or a saddle, its colour range and colormap.

  • Share: the whole session as a link. §5.5 says the URL carries what is being looked at and the session file says the rest; both stay true, and neither serves the case between them — somebody wants to send a colleague what they are looking at, right now. A link carries none of the work, and a file has to be attached, downloaded and dropped, by which time the moment has gone.

    So the session — the view, the tracks with their colours and limits, the marks, the bookmarks — is deflated and base64url-encoded into the fragment. That choice is the privacy property, not an implementation detail: a fragment is never sent on navigation, so what somebody is looking at never reaches the host serving the page. Nothing holds the link, so it cannot expire, cannot be taken down, works offline and works in the desktop build.

    What it costs is length, and length is the cheapest of those to give up — a few hundred characters for a view, a few thousand for a workspace. The dialog says the number when it gets large rather than guessing on the reader’s behalf: they know where they are about to paste it and the app does not.

    A third-party shortener is offered beside it, never instead of it, and is named in the button rather than hidden behind a verb, because it breaks two of those properties: the link starts depending on somebody else’s service, and the address of the file being viewed leaves the browser. It is refused outright for a session over a local file — the long link is still worth having there, the recipient getting the tracks and the marks and being asked for the file, but shortening it would post a filename to a stranger in exchange for nothing. If the service cannot be reached the long link is untouched and stays on screen.

  • bedGraph and wig open as tracks, which closes an asymmetry that was invisible and slightly embarrassing: the app wrote bedGraph — every analysis result offers the button — and could not read one back.   • A tabix sidecar makes a feature file a bounded read. Every other read here already was — HDF5 through range requests, a bigWig by zoom level, a .hic by the blocks its rectangle covers — and then a GTF was downloaded whole. The demo file is 9.5 MB; GENCODE is five times that.

    Where a .gz is BGZF and a .tbi is beside it — dropped alongside, or at the conventional <url>.tbi — only the byte spans holding the sequences this map is about are fetched. Against a map of one chromosome that is about a twentieth of GENCODE. BGZF and the index are read here rather than depended on, for the reason hic/format.ts gives at length: the byte layer, its LRU, its request accounting and its S3 signature belong to ByteSource, and a parser that fetches for itself sits outside all three.

    The fallbacks are the feature. A plain GTF still works, a bgzipped one with no index still works, and an index that is absent, corrupt, truncated or for another assembly falls back to the whole-file read rather than refusing the track — an index that can prevent a file from opening is worse than no index. A sidecar is only asked for when the file is a .gz; a span set covering more than four fifths of the file is abandoned as no saving; and sequence names are matched through the chr prefix in both directions, because Ensembl writes 1 where UCSC writes chr1 and reading the whole file over that would be the index quietly not working.

    One thing worth knowing before touching it: the fetch has to over-ask by up to 64 KiB, because a span ends at the start of the last block holding a record and a block’s length is not knowable without reading its header. The decode is bounded separately. Without that, a one-sequence read on a densely packed file hands back the several sequences that happened to follow it — which the suite caught, and which reads as the index working.

  • .hic files open, and nothing downstream can tell. Versions 7, 8 and 9, local and remote, at every base-pair resolution the file carries. This is where the published record is: most mammalian Hi-C on 4DN, ENCODE and GEO is distributed as .hic and as nothing else, and until now this viewer could not be pointed at any of it.

    It costs no constraint. A .hic is block-indexed with a master index at a known offset, so a region is a bounded range read through the same ByteSource as everything else — the same 1 MiB LRU, the same §12 request accounting, the same S3 signature for a private bucket. A block is not a tile: nothing is composited, nothing is cached to be assembled, and a read hands up one whole bounded matrix in COO exactly as a cooler’s does. If anything the format suits §2 better than HDF5 does, its index being two-dimensional — so the off-diagonal rectangle this application exists to draw costs the blocks it covers rather than a whole row band across the genome.

    The integration is two modules and a seam rather than a second reader. hic/handle.ts answers the questions a cooler’s HDF5 groups answer — a chrom table, an offset array, root attributes, a weight column — and metacooler/store.ts draws a PixelStore seam at the operation rather than at the dataset, because the one thing a .hic genuinely cannot pretend to have is a globally sorted pixel table.     Checked three ways, and the third is the one that earned its place. Fixtures whose contents are known exactly, across every encoding the format allows — v7/v8/v9, short and float values, short and int positions, list-of-rows and dense blocks, grid and diagonal block numbering. Both the lead’s rule and the companions’ fallback are now the size the panel measured, and test/unit/deck-plot-css.test.ts keeps them numbers — the same fault had already been fixed once for a turned companion’s height.

  • A turned map now takes the room it is given, whenever the room changes. A band’s rectangle is the one picture in this app whose size is a number the panel computes rather than a length the stylesheet sets, and only some of the roads into it redrew that number. So the band kept the width of the window it was first drawn in: folding two columns handed it three hundred pixels it never took, pressing the turn toggle drew it to a room measured before the fold, and a window resized around it left it where it was. All four roads — the shell folding a column, the view’s own resize observer for a window or a new lane, a turn arriving or leaving, and a deck relaying out — now end in one place that re-measures the room and redraws the box, and the band’s depth follows on the next frame as it always did. A width the reader dragged is still theirs: it is clamped to the room rather than grown into it, and a double-click on the handle gives back “as much as there is room for”.

  • The band on a long chromosome aliased while scrolling into it. Pooling caps each axis on its own, which is right for a genome pair — the two axes are two different sequences, and halving the short one to suit the long one loses detail nothing asked for. On a turned band the two axes are one measure: the rotation is isometric, so a raster pixel four cells across and two up is drawn as a rectangle where the geometry promises a square. E. coli at 1 kb turned is 9,281 × 4,039, which pooled to 4 × 2 — and then every decision downstream had one answer for two scales. At the crossover the x axis was magnified through a blur while y was still point-sampled; past it, nearest neighbour laid cells down two device pixels wide and one tall. Against structure that runs at 45° that is a cross-hatch of smeared diagonals over the whole band, which is what a reader saw as aliasing at the very zooms they had scrolled in to look closely.

    A turned band now pools with one stride on both axes, so its raster pixels are square in matrix space, the filter question has one answer, and the pyramid level is the right one for both directions. It costs no memory (E. coli’s band is 4.2 M pixels where it was 4.7 M) and no detail worth having: the axis that loses resolution is the one that was already being drawn at three cells per device pixel, and zooming in re-reads the window at a finer grid anyway.

  • Marks could not be placed by pointing at a turned map, which is every map a region view opens. pick on map collected nothing and the right-click Mark this point menu did not open at all — silently, both of them, because a click that places nothing looks exactly like a click that missed. Typing coordinates worked and the marks drew correctly once they existed, so the feature looked broken in the one presentation it is most useful in.

    One conversion is behind both gestures: a cell into the pair of loci a mark names, one per axis, which is what lets a single click serve a line, a crosshair and a loop. It read the loci off the axes the picture is drawn against, and on a turned map the row axis of that pair is deliberately absent — y there is distance from the diagonal, which is not a place, and x is counted in half bins. The cell is now taken back to the square it was rotated out of and read against that block’s own two axes, which is what the tooltip, the readout and the region-opening selection have always done. Clicking a dot in the band therefore marks the loop it is: the two ends of the contact, 10 kb apart at ten rows up, rather than nothing at all.

  • The three track tasks failed with “nothing is open” in a session that has no contact map. A metaplot, a track correlation and an interval overlap read the loaded tracks and never touch a matrix (§18.3) — the 1D browser session is exactly where a reader has the bigWigs and not the map, and the panel is offered there deliberately. Everything on the way was ready for it: the context is built without a file, the framing falls back to one over the tracks. The last line still assuming a matrix was the target a result is filed under, which came from the open file and so from nothing at all.

    It now comes from the genome the tracks were loaded against, and a target with no file behind it is no longer a broken target: a chain that mounts nothing does not need something to mount. A map task that reaches one refuses in its own words — Diamond insulation reads a contact map, and this session is browsing a genome without one — instead of the queue’s old “nothing is open” for a session with a genome and nine tracks in it.

  • The map aliased near the diagonal on screen while the exported figure did not. A canvas filter is one bilinear tap: it reads a 2 × 2 neighbourhood per destination pixel, which is a filter down to a halving and a fiction past it. A whole chromosome at 1 kb is a 3,000-pixel raster drawn into 460, so seven cells of every eight were never read — and on a turned map, whose lattice is half a bin and shifts parity row by row, what beat against the pixel grid was a moiré of diagonal stripes across the band. The export was spared because 300 dpi is three times the density: the same tap had a fifth of the work to do.

    The view now keeps halved copies of the raster and samples the one nearest the size it is drawing, so the filter is never asked to reduce by more than a half — which is the one reduction it does honestly. Levels are built on demand and dropped with the raster: a region view drawn a pixel per bin builds none, and no level is ever built for a frame that does not ask for it. Magnified pictures are untouched, still nearest-neighbour, still crisp to the bin.
