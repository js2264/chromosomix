chromosomix 0.13.0

What changed in chromosomix 0.13.0, released on 20 September 2026.

Added

Section titled “Added”

  • A box drawn over any chart is a zoom; a double click undoes it (§18.13). Hold ⌘ — or Ctrl, which is the same key on the other two platforms — and drag a marquee over a figure, and the axes come back holding what was inside it. Which axes it sets is read off the shape of the drag, with no mode to be in and nothing to choose first: a flick across the picture sets the abscissa and leaves the ordinate alone, a flick down it sets the ordinate, and a box sets both. The rule is a share of the axis rather than a count of pixels, so it reads the same in a folded drawer and in a full window, and a press that went nowhere is a click. A double click inside the plot puts both axes back to the windows a control last set — the numbers a reader typed, or the whole of the data where they typed none. The wheel still zooms one axis at a time, which is the right gesture for following a curve along; this is the one for arriving somewhere, which used to take a scroll and a pan on each axis, overshooting at every notch.

  • A result matrix is an interactive heatmap (§18.13). A saddle, a pileup, a cis/trans square and a track-correlation heatmap are now drawn by the same chart every curve is: the cells hover and name themselves, the colour bar’s handles clip the scale instead of captioning it, and the marquee and the wheel work on them as they do everywhere else. The colours are still this application’s own tables and the scale is still the painter’s rule, so a saddle in the drawer and a saddle in a paper are the same picture. Contact maps are untouched — a raster of millions of cells is not a thing a heatmap series could ever be — and so is any result matrix above twenty thousand cells, where half a million rectangles in an SVG would be a picture nobody can point at.

    The cells stay square where both axes are the same quantity, whatever the reader did to the drawer, because a saddle is read by comparing its two corners and a corner stretched 40% along one axis looks stronger than the one opposite it.

  • The metaplot’s per-feature heatmap takes the whole width of the card (§18.13). Its rows are a list — one feature per row, strongest first — and nothing is compared across a diagonal it does not have, so square cells only made it a ribbon a fifth of the card wide with white on either side. It now fills the card under the profile it shares an abscissa with, the way every metaplot tool draws it, with that abscissa numbered so the two pictures can be lined up at all. Its colours are clipped at the 99th percentile rather than fitted to the extremes: one feature under an amplification, or a single bin of pile-up artefact, used to take the whole scale and draw every other row at the bottom colour — a flat block with a colour bar running to thirteen hundred. Cells above the clip keep the end colour, so an extreme row is still visibly extreme.

  • Every figure a task produces is now restylable, and the PDF is still a drawing (§18.13). A slim strip over each plot carries the controls reached for constantly — the mark, the two log axes, the legend, Fit — and one button beside it opens the figure in the same dialog the 3D model opens in: the picture at the size of the window, every control in a resizable column beside it. There are new marks to choose from (line, area, step, points, bars; histogram, box and violin as summaries of the ordinate), per-series colours and visibility, typed axis windows, and a title and type size that go into the export. A table is now a view rather than a printing — filter it, sort it, choose its columns, or draw one numeric column as a distribution or against another as a scatter. All of it is remembered per file, per task and per output, beside the parameters the task was run with, and carried in an exported session.

    Contact maps are drawn exactly as they were, by the same rasteriser: a contact map is a raster of up to sixteen million cells with its own gestures and its own export path. A task’s result matrix is a chart now — see below.

    The PDF export is still a true vector page — paths and text, restylable and scalable, not a photograph. The chart library is asked for SVG rather than for a canvas, and the same picture is replayed onto whatever context the export hands over, so the screen, the PNG and the PDF are one drawing rather than three. The library itself arrives in a chunk of its own when the first figure is built, so a reader who never runs an analysis never downloads it.

  • A 3D structure viewer, as a full view of the app (§25.3–25.5). A chromatin model — WashU’s g3d (the text g3dtools takes, or the binary container written here), a .3dg, or bed3d (the same file with an end column) — becomes a row of the Structures card (under Tracks) and a cell of the deck; a .g3d can be dropped on either card, since the loader files it as a structure either way. three.js loads only when a structure cell first opens (a 552 kB chunk, 140 kB gzipped). Its settings sit on a 3D structure card of the Aesthetics panel, right after the Map card, shared with the enlarge dialog’s sidebar: size by a track, a depth slab into a dense model (the fog is tied to it — measured from the centre of rotation, so it actually clips, rather than from the camera), a genomic ruler along each chain, camera presets, a turntable, and the cell’s actions as palette commands (f, a, 1–3, l, r). Drawn-as is three combining icon toggles (beads, sticks, tube); every chain gap is always a dashed run of ink and the gaps option is gone; the cell is always orthographic and lit, so those two options are gone too; fog, chords, names and centre are icon toggles; one ghost opacity slider (0.15 default) covers what is outside the window or ghosted from the key, and outside the window: show draws a whole genome in colour while the maps look at one window of it. A stored style still reads back, the old representation becoming the three toggles.

    Colour by sequence — the key is a control: click ghosts a sequence, double-click shows it alone, the swatch is a colour picker — haplotype, position, the file’s own columns, a loaded track, a feature set, the reader’s marks, distance to the pinned bead, or contacts from the pin, the map’s own row through it drawn as chords above a threshold on the map’s colour scale. Compare with superposes another structure by a similarity fit over the beads the two share, reports the RMSD, and colour by displacement shows where they differ. Hover links every surface: a pointer on a map lights the beads at both ends and joins them (or, with the span modifier held, lights one bead); a pointer on a bead marks every map and tracks cell; a card under the pointer names the bead’s sequence and coordinate; the pointer snaps to the nearest bead within 14 px with a cross cursor while it is aiming; the eye on a Structures row opens and closes the model’s cell in the deck. Marks are three modes, a button and a key each — mark a bead (e), mark a loop (o), measure (m) — replacing a click-counter that had to guess which was meant: a mark is the bead again at twice the radius in the mark’s colour, a measurement a drag between two beads with the model holding still, and select mode turns clicks into manual marks the same way on a map (two beads an arrowhead, offered as chords under your marks). The black lines over the model — a gap’s dashes, a loop’s chord — are half the tube’s radius. A badge in the cell’s corner says what a drag or click does; single-letter keys are bound only while the model is enlarged, so they no longer steal f/a from the Files/Annotations panels when a model sits beside a map. The enlarge dialog’s sidebar is dragged to any width, remembered per file — the cell takes back the camera and colouring the reader left it with. A click pins, Shift-click marks, a double-click goes; bookmarks are named on the model; the export includes a vector PDF of beads and sticks.

    The place under the pointer is always named in the cell’s corner, including on the model itself — one locus there, where a contact from a map is a pair. The sequence box of every structure task is seeded from what the map already shows (the locus inside one sequence, every sequence on screen when it spans several, empty for the whole genome); a model computed again onto the same row replaces the one the cell draws, and removing it empties the cell however it arrived there. Two analysis tasks: model versus map (distance matrices, distance by separation beside the map’s P(s), Spearman agreement per sequence) and spatial tracks (radial position, distance to a locus, local compaction, as synthetic tracks). The deck gains cells that are not maps (§16.11): a tracks cell drawing the session’s tracks alone, and the browser as lead, so a deck of tracks and a structure needs no map at all — the lead’s window ghosts what the maps are not looking at. Demo models ship for the E. coli and yeast maps under demo/.

  • Model from the map builds one bead per bin, with no ceiling (§25.6). The map task that makes a structure from the contacts the view is holding — the whole loaded block, cis and trans, by ShRec3D (contacts as distances c^(−1/α), uncounted pairs filled, classical MDS) with SMACOF refinement, each pair weighted by how often the map counted it (count, its square root, or uniform — count by default; α and the step count exposed, a sequence or typed range restricts it, a table reports the fit) — now builds a bead per bin at the resolution selected. The bins per bead control, and the silent pooling that used to cap a model at the raster’s 4,096-cell ceiling, are both gone: a coarser model is a coarser rung, which reads far less, rather than the one task in the app whose answer came at the window’s resolution instead of the reader’s own choice.

    The bead ceiling is gone with it. Both time and memory are quadratic, so the cost estimate says so — beads and their width, seconds per hundred steps, gigabytes of matrices — and the reader decides; only an allocation the browser will not give is refused, as a named error rather than a dead tab. The run holds two dense matrices where it held six, each built once at its final size; every phase — each rectangle read, each of the eighty sweeps of the classical start, each refinement step — reports progress, so the bar moves and a cancel always lands. A typed locus is priced as the bins of that stretch; over 10,000 beads is refused with the way out.

    The result is a row, not a picture: every model the session holds — dropped, named by URL, or computed — is listed on the Structures card with show in the deck, a bed3d download, the provenance of a computed row, and recompute after a reload; the structure cell gains a model picker, remembered per file, and draws a model the moment it arrives.

  • Track aggregates along a pileup’s two edges (§18.8). The APA takes any number of bigWig or synthetic tracks and averages each over the same windows the pileup is taken from — the real ones, never the shifted controls, which are the denominator of the picture rather than the picture — drawing them as profiles above it and beside it. That is the figure most papers using an APA actually print: the aggregate contact map with the aggregate signal on its edges, which turns these places touch into these places touch, and this is what is bound where they do. Until now a reader had to run the 1D metaplot separately over anchors they re-derived by hand, and the two aggregates were over different windows unless every setting happened to agree. Each profile is normalised on its own — two tracks in two units have no common axis, and what a marginal promises is the shape along the window — and is resampled by the window’s own grid edges, so a cell of the profile is the cell of the pileup above it by construction rather than by a second resampling that could land a domain boundary a column out. MatrixOutput.margins is the general mechanism; the figure counts the bands in the height it asks for, or the top one would be clipped away.

  • The loop spectrum: a called set’s score against how far apart its anchors are (§18.8). The plot neither of the two figures beside it can give, because both average the distance away — a pileup is a mean over windows at every separation the scan covered, and the score histogram counts scores with no regard to where they came from. So a set whose 30 kb calls are loops and whose 2 Mb calls are noise is a plausible dot under a clean unimodal peak. Against distance the two commonest ways a loop set is wrong are visible at a glance: scores that fall away with separation are a detector reporting the distance decay it failed to remove, and scores piled against the minimum-distance cutoff are calls made on the diagonal’s own shoulder. A cloud of points with a median line through it in log-spaced bands — the points are where the calls are, spread included; the line is the trend, in bands rather than a fit because nothing claims the relationship has a shape, and a median because a tail is exactly what is being looked for. Returned by the chromosight detector, by the chromosight pileup and by the ordinary APA over a loop set, where the ordinate is each anchor’s own P2LL.

  • An APA window is cut about the point of the feature the reader chooses (§18.8) — start, centre or end, strand-aware, the same three the 1D metaplot has offered since it existed and spelled the same way. It took the midpoint and never said so, which on a gene set is a pileup at whatever is half way along a gene rather than the figure anybody draws, which is the one at the transcription start site — and a metaplot set to start and a pileup beside it were then aggregates of two different anchor sets under one caption. The chosen point is also what a generated pair’s separation is measured between, or the range and the picture would disagree about which pairs they are of, and the axis label says which point it is: bins from the centre over a pileup of four thousand TSSs is a caption for a figure nobody drew.

  • Previous runs are kept, and there is a way back to them (§18.4). Pressing Run used to replace a result in place, taking the figure, the numbers and the parameters that produced them with it — and nothing about a finished result makes it cheap to produce again: a pileup over forty thousand anchors is a minute of range requests. The runner keeps the last eight runs of each task on each map, and the drawer offers older / newer / latest over them with each run’s clock time and, in its tooltip, which parameter differs from the latest. Everything downstream follows the run on screen — the framing line, recompute, the CLI command, the TSV and the vector export are all that run’s, because a result is a record and stepping back to one means stepping back to all of it. Not persisted, for the reason the framing is a snapshot: a history restored against a file that has since been re-binned would be a list of figures that no longer describe anything.

  • Zoom, as four buttons beside the region box (§5.4). The scroll wheel on the map zooms the picture — the same block, drawn larger or smaller — and past the edge of what was read it stops. This is the other thing a genome browser means by zooming: a different range, re-read, with the region string updated to say so. The four are 10× and 3× out and 3× and 10× in, widest first, so the row reads as one axis of scale with the window you are on in the middle of it, and each is the exact undo of the one opposite. Two sizes rather than one because a single step is always wrong twice — three presses to leave a gene, or one press past the locus. Every press moves about the window’s own centre. Against an end of the sequence the window slides in rather than asking for a negative coordinate; once a press outward would cover the whole sequence it is the whole sequence, named as such; inward it stops at the file’s own bin size; and on a declared circle it wraps past the origin rather than clamping. Each greys itself when there is nothing in its direction to go to, and they navigate through the ordinary road, so three presses and three presses of the back button are the same journey in reverse.

    Zooming out is also what finally made a window across a circular origin reachable: the panel refused to name one window where the axis showed a sequence’s tail and then its head, so the button greyed itself on exactly the view zooming out is most interesting from. Two runs of one sequence is one window on a circle, and it is reported as the region a reader would type — flagged as wrapped, because the Bookmarks card cannot write one as a BED interval and now says so in those words rather than claiming the picture is not at one place.

  • A resolution the file does not store, on the fly (§3.4). A + past the coarse end of the resolution picker asks for one, and what can be given is exactly what is a whole number of some stored rung’s bins added up. That covers both things a reader wants and neither of which a published .mcool reliably has: a coarser picture than its coarsest rung — 10 kb from a file that stops at 4 kb — and one between two rungs, like 3 kb on a 1 / 2 / 5 / 10 kb ladder, which is three 1 kb bins and not a number anybody would have run zoomify for. 2.5 kb on that same ladder cannot be given, because a contact is recorded in a bin rather than at a position inside one, and the dialog says so in those words as the number is typed rather than greying its own button: not a whole number of bins of any resolution this file carries tells you to type 2 or 3. Where several rungs divide the target the coarsest is used — same picture, a twentieth of the stored pixels walked.

    It behaves as a resolution and not as a rendering. The grid is anchored to each sequence’s own start, so the same base pair holds the same sum at every pan and every zoom, which is the grid a real coarse cooler has; the zoom-to-refine ladder takes it as a floor and never reads past it; the whole-genome view takes it as a floor too and its own plan still wins where the picture cannot hold that many cells; and it rides in the link beside balance=, because a 10 kb map and a 1 kb map of one window are different pictures. Which resolutions you have added is a fact about the file, kept per file and carried in an exported workspace beside the sequences you declared circular. An added rung wears a * in the picker — in the label, because the number is what gets quoted in a methods section and this one is not in the file — sorts where its number says, 3 kb before 5 kb, and carries a × the file’s own rungs do not.

    One caveat, printed every time it is offered: counts add up exactly and balanced values do not. cooler zoomify --balance sums raw counts and then balances the coarse matrix at its own resolution; this applies the fine weights and adds the results, which is what every aggregation in this field does and is a good estimate rather than the same number.

  • An APA’s edge profiles are one aggregate over both anchors of every pair (§18.8). Which anchor of a loop is written first in a BEDPE is whichever sits further left on the sequence, and nothing else: it is not upstream in any biological sense, not the cause of the contact, not the end with the factor on it. Profiled apart — which is what the edges did — the top of the pileup was every pair’s second anchor and its right side every pair’s first, so the two lines differed by whatever that arbitrary ordering happened to sort, and a reader comparing them read a difference between the two ends of a loop that the file never claimed. Each window now contributes both of its anchors to both edges, which is one mean over twice as many anchors: better estimated as well as honest. Pooled a window at a time rather than by averaging the two finished profiles, since the accumulators count per cell and a cell one of them never saw would otherwise be weighted as though it had. A tickbox turns it off for the file where the ordering is the figure — a BEDPE whose left column is always the promoter, say — and it is offered only off the diagonal, where the two axes cut the same window from the same feature and the two profiles are already the same numbers.

  • A barChart lane takes a fixed value axis (§8.17). Both readings the format had were relative — every chart against the file’s tallest bar, or each against its own — so a GTEx lane and a knockdown’s lane laid side by side are each scaled to their own maximum, and the one with the quieter tail draws the taller bars and looks like more expression. The lane now carries the same limits row a signal track has, meaning the same thing: auto is what it always did, and a typed pair is an axis the bars are drawn against. It overrides the per-chart switch rather than composing with it, reaches the collapsed glyph so a lane zoomed out does not quietly change what its heights mean, clamps at both ends, and states both of its ends in the line under the lane’s name — which is what makes the comparison it exists for possible.

  • A window may be typed straight across a circular sequence’s origin (§8.15). chrom:2,900,000-100,000 is now a legal region on a declared sequence: cooler refuses an end below its start, correctly, because on a line it is a typing mistake — and on a circle it is the 200 kb either side of the origin, which is where the most local contacts are and is the one window a linear reading cannot ask for at all. The refusal is lifted for exactly the sequences the reader has declared; every other range keeps cooler’s own error, now with a sentence on it saying where the tick is, because a reader who typed one usually meant it. A bad range also stays inline over an intact region box rather than reaching the full-screen error page, which was a long way back from a missing comma.

  • The store grid: Roadmap shipped as a hub, a link to whoever made each shelf, and two doors named for what they do (§24.2, §24.10).

    Roadmap (UCSC hub) is a sixth built-in store, reading WashU’s hub over the 111 reference epigenomes. It is the first shipped store that is somebody else’s hub rather than a file this project generates — no shard list, no stores/ entry, no workflow, no front of its own, just a hub.txt URL and the same fetchStore every store URL already went through. Its rows are read on the gesture that opens it, so the tile costs no request.

    Every store now links to the people who made it, from an arrow beside the download in the drawer’s head: RSG’s team page, IGV’s genome documentation, 4DN’s portal, ENCODE’s matrix, DNA Zoo, Roadmap’s WashU portal, and UCSC’s hgHubConnect on the hub door. A store is somebody else’s data and the rows are a translation of their catalogue, carrying none of the licence, citation or caveats they wrote down; this is the whole of what the viewer does about that. It is drawn as soon as a store is opened, read or not — the reader whose catalogue just failed to load is exactly the one who wants the site behind it.

    The two doors are named for the errand: A track hub is now Connect to a UCSC hub — a hub is somebody else’s shelf, read where it stands, which is what connect means everywhere else on the page — and Your own store is Add a custom store, a file this viewer takes a copy of. The first wears UCSC’s logo, and so does every hub a reader remembers; Roadmap wears its own emblem over UCSC’s colour. The second wears this viewer’s own icon, the file behind it being the one format in the grid written for this viewer rather than translated into it.

    The grid wraps. It was one row that could not, which was right while there were five tiles; there are eight now and a reader can connect more, so it is equal columns that fill the width and spill onto the next line, with the last line’s tiles the width of the ones above them.

    scripts/make-store-logos.mjs grew three things to carry the new marks. An incremental run, so adding a logo no longer means re-obtaining the four whose sources are not committed. A bleed fit for a mark that is already a tile — the app icon is a squircle plate with its own margin and shadow, and containing it on white drew a plate inside a plate. And a crop, for a logo too long to letterbox: Roadmap’s is 958x208, which whole would have set its wordmark at about five pixels on the landing page, so what is taken is the square at its left end.

  • Five UCSC formats, and track hubs as stores (§8.18–§8.21, §24.10). Everything below is one change with one shape: the formats UCSC’s browser reads that this one did not, and the index most of the world’s published data is actually behind.

    interact and bigInteract, longrange and longTabix (§8.18). UCSC’s interaction formats, which are the only ones it has that are about the thing this application is about: two places joined. Both become a PairSet — what a bedpe becomes — so both arrive drawn, as arcs across the matrix and as their own lane in the 1D browser, with no renderer written for either. Trans interactions survive as ordinary off-diagonal arcs rather than as the labelled edge marker a single axis forces on UCSC.

    This is a correctness fix and not only an addition. Both formats are BED-shaped enough to reach the BED sniffer, whose last line is return 'bed', so neither was refused: an interact with a fractional value — UCSC’s own examples write 5.000000 — was drawn as one box spanning both anchors and the gap between them, and an interact whose value happened to be a whole number matched the bedpe rule and was read as one, putting the interaction’s name in the second contig and its display score in the second start. Arcs, drawn confidently, between coordinates that were never in the file. A longrange was a BED4 whose names were the coordinates of the arcs it should have drawn. A longrange’s reciprocal lines — the format writes every interaction twice so that a tabix query from either end finds it — are folded, and the lane says how many it folded, rather than every loop being drawn twice and every count being wrong by a factor of two.

    genePred, genePredExt and refFlat (§8.19). How the gene models of half the assemblies in circulation are distributed, and the gap with a number on it: the IGV store this project publishes was dropping 29 of IGV’s 63 tracks because they are UCSC genePred tables in a .txt.gz, and those 29 are the gene models — the first track anybody wants beside a sequence. They are published now. The same ten columns start at column 0, 1 or 2 depending on whether the file is a refFlat and whether it carries a MySQL dump’s bin index, and eleven columns is ambiguous between the two — so the offset is not guessed from the width but found, by keeping the one where the file agrees with itself: a strand where a strand goes, and two comma lists whose length is the exon count and whose blocks tile the transcript. A bigGenePred already drew correctly, its first twelve columns being a BED12; what its schema now buys is being a gene model rather than a peak set.

    bedMethyl and bigMethyl (§8.20). Base-resolution modification calls, as the quantitative track they are — percent modified per base, with the range, ceiling, autoscale and colour every bigWig lane has. Read as the BED9 they begin with, which is what happened before, they were a lane of grey boxes one base wide with the measurement never mentioned. A file holding two modifications over the same bases draws the more abundant one and says which it did not draw, because those are two measurements and averaging them would produce a number that is in no file. The metagenomic case is the one this was really added for: bacterial 6mA and 4mC are strain-specific and are used to bin contigs, which is what the MAG layer is for.

    .2bit (§8.21). UCSC’s packed sequence format, read by range. One file rather than a FASTA and a .fai — so every way §8.8’s index goes missing simply cannot arise — at two bits a base instead of eight, which is 800 MB for hg38 against 3.1 GB. The gaps are read from the N blocks and painted over the unpacked bases, because the bits under a centromere are not blank but a convincing run of thymine; the mask blocks are stepped over and never fetched, being eight megabytes a chromosome for a lowercase this viewer discards twice over. A long (version 1) .2bit is refused by name rather than misread as wrong residues. The CLI reads one the same way, through the same arithmetic.

    UCSC track hubs, as stores (§24.10). Paste a hub.txt and its genomes and tracks become a shelf: grouped by assembly, narrowed by the hub’s own composite and super-track names, with open with its tracks on every assembly’s heading. An assembly hub opens its own .2bit as the genome — which is why that format is in the same release, since without it every assembly hub opens as tracks over coordinates nothing can read — and a db hub, which carries no sequence, falls back to its chromSizes and then to the first bbi file in its own trackDb — any big* type, a bigBarChart and a bigMethyl being bigBeds with a particular autoSql and nothing else — whose header carries the lengths. It never reaches for a chrom.sizes nobody asked for.

    A hub is recognised from its content at the one function every store URL already goes through, so a hub works in ?store=, in the Connect box, as a remembered tile and in a shared link, and none of those had to learn the word — while a JSON store served from a file called hub.txt still opens as a store.   • A large FASTA opens at once, through its index. Opening IGV’s Galgal6 — a gigabyte of sequence — read the whole file into the annotations worker before the browser could appear, or refused it past 300 MB, because a FASTA was the one format held whole: every sequence in memory, which is what made every zoom draw GC content and every pan free.   • This chromosome is circular — and then the map slides round it. A tickbox in the Map card, on any view that is a window on one sequence (SPECS §8.15). A .cool cannot say that a sequence joins its own ends, and nothing can infer it — a bright far corner is a circular chromosome, or a translocation, or an assembly error — so it is a declaration, kept per file and carried in an exported workspace.

    With it the window becomes unwrapped: it runs off either end of the sequence and comes back on at the other, so a square across the junction is up to four stored blocks, one of which is the far corner where the contacts joining the two ends of the molecule live. Panning past the end reads the same block width rotated round to where you now are — in the square view and under the turn alike, and with no limit but one lap, past which a bin would be drawn twice. Ticks, the coordinate readout, tracks, features and hand-drawn marks survive the join, because the block’s axis carries the sequence twice and says which lap each half is on; a mark is now drawn at every place its locus lands rather than the first, or it would flicker in and out as you slid past the junction.

    And the numbers follow, automatically and with no per-task tickbox: the separation between two bins becomes the shorter of the two ways round, and the longest separation a sequence has becomes half of it. P(s) stops turning back up at the far end — that upturn is the two ends of the molecule wearing a chromosome-long separation, and every fit through it is a fit through an artefact — diamond insulation scores the bins at the junction it used to leave as gaps, and the directionality index, the HiC score and the scalogram wrap with them. What does not yet: compartments, chromosight and the O/E map divide by an expected curve at a linear separation, and a deck companion draws the sequence linearly. Both are stated at §8.15 rather than left to be found.

  • Three more readings of the near-diagonal, and a fourth normalisation for the 4C. The catalogue (SPECS §18.8) gains the directionality index — Dixon et al.’s signed χ², the other answer to the question the diamond asks, with its window in bins like the diamond’s and defaulting to 50, which is Dixon’s 2 Mb at the 40 kb his paper worked at; the HiC score, the sum of every cell in a square window centred on each bin, which is the reading Bignaud et al. use where the question is how tightly a stretch is folded rather than where a domain ends; and the scalogram (Cournac et al. 2012, HiContacts::scalogram()), which is P(s) with one summation left undone — at every bin, the separations at which its contacts reach each of a set of quantiles. All three read a band and never a square, so a 2 Mb window on a mammalian chromosome is a run rather than a refusal.

    The 4C’s Normalisation becomes one control with four answers — none, by coverage, by P(s), by both. Coverage is the other bias and a different one: the decay is a property of separation, coverage is a property of the target bin, and on a raw map a repeat-rich bin is a dip in every profile drawn against it whatever the anchor. The divisor is each bin’s own total contact centred on one, so a raw profile stays in contacts and an O/E ratio stays centred on one. With trans it means the pixel walk can no longer stop at the anchor, and the estimate says the pass is the whole file rather than half of it.

  • The directionality index calls TAD borders and domains. The same two overlays the diamond produces, and through the same kernel. A domain reads as a shape along the index — the 5′ half looks downstream, the 3′ half upstream — so a border is the negative-to-positive flip between two of them. Called flip by flip that is fragile: a track that stutters across zero has crossings a bin apart and only one is an edge, and the rules that pick it are the rules of prominence written out badly. So the index is integrated first. The running sum climbs through every downstream-biased block and falls through every upstream-biased one, which makes each border a local minimum and each stutter a dimple on the flank of the real trough — exactly what callBoundaries already distinguishes, for the diamond, with tests. One implementation decides what a called edge is; both overlays filter on the same column and tile the same way; and the call lands one bin past the minimum, which is the opening bin of the new domain rather than the closing bin of the old one.

    The curve is standardised by the median absolute index before it is integrated, so the prominence is in bins of ordinary directional bias rather than in χ². A χ² grows with how deep the library was sequenced, so a threshold in the index’s own units is a different threshold on every file; this one is a property of the structure, and a value found on one map is worth typing into the next. Dixon’s own HMM differs in one visible way, stated at §18.8 rather than left to be discovered: it leaves stretches it calls unorganised in no domain at all, where borders-between-borders tile.

  • Ribbons: a lane style for a set of quantiles (SPECS §18.12). A ribbon fills the band between its own curve and the curve of the member below it in the same lane, so the scalogram’s five quantiles draw as one nested shape rather than five lines and a legend. Four filled areas cannot express that — they paint over each other in the order they were drawn. Ribbons tile rather than overlay, so they are not dimmed; the lane’s order is the nesting order; a band exists only where both its curves do; and only the top edge of each is stroked, since the lower one is the neighbour’s. A ProfileOutput may now also suggest a display scale, which is what puts the scalogram on a log axis — its values are genomic separations, and on a linear axis all five bands live in the bottom tenth of the lane.

  • Genomic features are drawn as what they are: coloured by strand, pointing the way they run, and banded so the two strands are two places. Every interval lane — a BED, a peak set, a bigBed, a gene model, a VCF — used to be one flat colour with the direction hidden in a tooltip, which meant a screenful of boxes said where and nothing else. Three changes, on all of them at once, because they are one renderer (§8.16):

    • Strand is the default colouring, in three colours: forward keeps the colour on the lane’s own chip, reverse is that hue turned most of the way round, and a feature whose file carries no strand takes the grey this app already draws an N in and already gives a variant with no single base behind it. The two hues come from the reader’s own colour rather than a fixed blue and red, so four peak sets on one screen are still told apart by the colours they were given — the same argument an alignment lane’s categories already make. A file with no strand in it — a peak set, most BEDs — keeps its one colour rather than turning entirely grey, since a grey meaning “no strand” says nothing where nothing has one.
    • A stranded feature is pointed. The head is cut out of the leading end rather than drawn past it, so the glyph covers exactly the bases the feature does and what is clicked is still what is drawn; a long one carries chevrons through it as well, so a segment spanning the window says its direction at every point. Below six pixels there is no head, because a pentagon three pixels wide is a rectangle that has lost a pixel. A gene with exons keeps the chevrons on its spine and takes no head — a point on its last exon would be a point on a piece of the gene rather than on the gene.
    • The rows are banded: unstranded, then forward, then reverse, outward from the map. Two genes on the same bases and opposite strands used to be two boxes one above the other with the difference carried entirely by colour. The bands are read from the file rather than from the window, so panning never rearranges the lane, and whether they fit is asked of the lane’s height rather than of the rows a label needs — so a segments lane at its default sixteen pixels, which is exactly where a stranded BED lands, bands into two rather than never banding at all. Below eight pixels a band would be a hairline, and the lane falls back to the packing it always had.

  • A drop-down on every interval lane, to colour the segments by any column the file carries. source, biotype, signal, -log10 q, QUAL, filter, score — whatever the parsers wrote. The keys are read back out of the joined attribute string each feature carries (§8.3’s decision, and this is what it costs), sampled across the whole file rather than its head, cached per set and bounded at twenty thousand rows — so a picker over a four-million-line annotation opens as fast as one over a BED with nine lines in it. A categorical column gets the same colour-vision-safe palette a metadata strip uses, handed out commonest-first with a twelfth-and-beyond other bucket; a numeric one gets a viridis ramp fitted to the file, never to the window — a colour that meant one thing before a pan and another after it is a legend that lies without saying so. The key sits in the card under the picker, built from the same function the renderer calls, and the chip on the lane’s name becomes a colour that is actually in the lane.

    A choice whose column the open file does not have is kept and marked rather than quietly corrected, because the same session opened against the other half of an experiment should colour by biotype again the moment the GTF comes back. Nothing here refetches: a feature set is in memory whole and a field is a column of it, so a dozen answers cost one repaint between them.

  • Five new analysis tasks, and two existing ones grown a question they could not answer. Every one of them is a measurement the app could not produce rather than a rearrangement of one it already draws, which is the line §18.9 draws and the reason each is argued where it is built.

    Reproducibility, across the maps on screen. The deck opens N files under one navigation, blends two in a square and overlays their curves — and every one of those answers do these look alike with a picture. The question people actually have is are these replicates, and its answer is a number. HiCRep’s stratum-adjusted correlation (Yang et al. 2017), ported: both maps smoothed with a 2D mean filter, each diagonal correlated separately — where the decay the two share is a constant and carries no variance — and the strata pooled by the Cochran–Mantel–Haenszel weight. Plain Pearson on two matrices comes out near 0.9 for two unrelated maps of the same assembly, which is why the stratifying is the method rather than a refinement of it. Reads a band rather than a square, so a mammalian chromosome is a few dozen bounded reads. Three outputs, and the third says more than the scalar does: the N×N coefficient matrix, the per-sequence table, and correlation against separation, which tells these agree near the diagonal and not far from it — a depth difference — from these disagree everywhere, which is two experiments. A map on a different bin grid is refused by name, because a stratum is a diagonal offset in bins and §16’s lock is in base pairs on purpose.

    Per-cell contact QC on an .scool. That container’s whole interaction is one decision — which cells to sum — and the Cells table could only rank them by nnz and sum, which is what the writer recorded and a statement about the sequencing rather than about the contacts. Depth is also the least interesting axis a single-cell library varies along: cells differ mostly by where in the cycle they were fixed, and a pseudo-bulk across phases smears exactly the structure somebody opened the file to see. Per cell, from its own pixels: contacts, cis fraction, and the share in each of four separation bands — Nagano et al. (2017)’s, whose near-against-mitotic scatter is the cell cycle drawn as a horseshoe. It costs what summing the same cells costs, to the read: the same reads in the same order, one accumulator per cell instead of one shared. The numbers land back in the Cells table as sortable columns, because the gesture they are for is the one that table already has — sort, tick a run of rows, sum them. No phase is assigned: the bands are a measurement with a citation and a cut through the horseshoe is a method with choices.

    Cis and trans per sequence, with the sequence × sequence square beside it. The first number any Hi-C paper quotes, per sequence rather than per bin, and the off-diagonal read against what the two sequences’ own trans coverage predicts under indifference. Above 1 is a translocation, a fusion, a centromere cluster or a Rabl configuration. It is the inter-MAG network’s own accumulation with the group being a contig rather than a genome — and it is not a translocation caller, for the reason §18.9 gives about any second caller.

    Fraction of signal in features — ChIP-seq’s FRiP, over any loaded tracks and any interval set. The covered fraction sits beside it and the ratio of the two is the column to read: thirty per cent of the signal in thirty per cent of the genome is a track with no preference at all.

    A shuffle null under interval overlap. Jaccard, shared bases and features hit are all descriptive and none has a scale, so how many of my loops sit on a boundary — the question §18.8 gives as the task’s whole reason — was not actually answerable. bedtools shuffle’s null: one set relocated at random within the sequences it already occupies, keeping its count and its lengths. Reported as a fold, a z and a permutation p on the tail the observation fell on, with Phipson and Smyth’s +1 so the p has a floor instead of coming out at zero.

    Every pair of a feature set, and pileups split by separation. APA gains a third anchor mode: rather than a loop set somebody produced, every pair of one feature set inside a separation range — which is the test a loaded BEDPE cannot be, since a BEDPE is already a claim about which pairs matter. And either off-diagonal mode may be split into log-spaced separation bands, each with its own pileup and its own control, because one pileup over 30 kb to 2 Mb is an average of a strong short-range contact and a weak long-range one.

    The four pair orientations, beside P(s). Read from the records during the import’s own pass and at record resolution, because binning sums the four together and destroys the one thing they are for: the separation at which ++, +−, −+ and −− converge is the shortest one a library can be believed at, and it is usually below whatever grid the reader chose. A .pairs that was never imported can be named in the form and read for its records alone. §3.7’s nothing about strands is read is narrowed in the open: its reason was filtering, no strand reaches a bin or a pixel or the written .mcool, and the pixels are identical whether the columns are there or not — which is asserted rather than claimed.

  • The HiC score is the mean of the bin’s own line across the near-diagonal, which is what the R the score comes from computes. It was the sum of every cell in a square window, and neither the shape nor the missing division was right.

    The shape. The score is now a[k, k + d] for |d| ≤ D − 1 — the bin’s column, reaching D − 1 bins each way — where it was every cell of a square centred on the bin. Drawn on a map that is a straight line through the diagonal: half a crosshair, one arm-pair, because the matrix is symmetric and taking both arms would count every off-diagonal contact twice against a main diagonal counted once. Every cell in it touches bin k. A square window does not have that property: it also counts the self-contact of k − 1 and the corner joining k − 1 to k + 1, cells that involve k in no way — and on a bacterial map at three diagonals those borrowed cells are most of the score, so consecutive bins shared half their cells and a single bright bin came out as a three-bin plateau. On Bignaud2025_T7.mcool a bin whose neighbours sit at 55% of it under the line reads 87% and 89% under the square.

    The division. It is a mean now: N = 2D − 1, the cells in the line. A sum grew with the number of diagonals and could only be compared against another run of the same size on the same map; a mean is contacts per cell and a lane labelled in contacts is readable as contacts. Multiplying by N returns the R script’s own number exactly — which is how this is checked: against Bignaud2025_T7.mcool::2000 at NC_000913.3:3,442,000 the kernel returns 3.7433 × 1/N where that script returns 3.7433, and the same at every neighbouring bin.

    The parameter is a count of diagonals, counting the main one, replacing a window in base pairs. It defaults to 3 — the main diagonal and the one either side, five cells, two bins each way — which is the bacterial reading at the 2 kb resolution the score is computed on there, and is the R script’s num_diagonals = 2 under the other way of counting. P(s)’s minimum separation and the diamond’s window went the same way and for the same reason: the near-diagonal is a fact about the grid rather than about the genome, and the same typed distance meant three diagonals at one resolution and one at the next. The runner says what the reach came to in base pairs on the file open and how many cells are behind each point of the track.

    The read is shallower: the band is D − 1 deep where the square needed twice its own reach for its corners — two bins at the default, one strip on most files, no tiling.

    A bin without a whole line through it now scores nothing. Dividing a short sum by a full N fades both ends of every linear sequence towards zero, which reads as this end of the chromosome is unstructured — the artefact the diamond has always refused partial windows for, and one that arrives the moment the reading becomes a mean. A circular sequence has no end to run off and every bin on one is still scored. A cell the balancer dropped inside a whole line is a different thing and is unchanged: counted rather than guessed at, never scaled up, and NaN below minValid.

    The task’s version is 3, so a result carried in from a shared session is not silently compared against one computed here. --window is gone; the parameter is --diagonals, and an old command line naming the old one is refused rather than quietly reinterpreted.

    One thing worth knowing and not fixed here, because it is a property of the data rather than of this task: at three diagonals the main diagonal is the bulk of the line, it is where self-ligation lands, and on a balanced map it is the one place the weights were never fitted — cooler excludes ignore_diags diagonals from its own solve and then scales them anyway. On the E. coli map above, the bin under that peak carries a balancing weight 1.45× its neighbours’, so its self-contact is scaled 2.09× and the peak is in the weights rather than in the counts, where neither statistic peaks at all. ignoreDiags = 1 cuts that cell out of the score, and the hint on the control now says why one might.

  • The number under a domain pileup is no longer P2LL.   • A pileup’s edge profiles were drawn from zero, which flattened them (§18.8). A ChIP aggregate running from 45 at the baseline to 92 at the anchor — a doubling — came out as a line across the top of a band three lines tall with a small bump in it, while the same numbers as a metaplot curve two blocks down the drawer were a peak twice the height of its baseline. Two pictures of one quantity disagreeing about whether anything happened, and the arithmetic was right in both. Each profile is now drawn against its own extent, with the two edges of one track sharing a ruler — they are one measurement — and the range printed beside the track’s name in the key, which is what keeps a self-scaled band honest about how much of an effect it is showing.

  • A pileup’s edge profiles now leave as numbers, with the matrix they belong to (§18.8). The TSV a reader exports carried the cells and not the lines drawn along them, which made the one thing in the figure with no numbers behind it. They are written as a second block under the matrix — contacts and signal are two units, and a spreadsheet reading them as one rectangle would average them together.

  • metacooler-run apa --tracks opened the file and then reported that it could not be read. A parameter that takes several entries files each one under key:entryId, which is how the app’s runner reads them back; the shell filed one vector under the bare key and read the parameter as a single string, so a pileup asked for at a command line came back with a note saying one of one tracks could not be read — about a file the command had just opened. The convention is now written down once and imported, rather than stated in two places.

  • A matrix figure’s colormap control drew empty on exactly the figures that set one. The slim strip offers six colours inline with the full list in the dialog, and a select whose value is not one of its options draws blank — so a saddle’s RdBu_r or a pileup’s fall made the control look broken. Whatever is in force is now offered alongside the six.

  • Fourteen rules in the stylesheet drew nothing, and looked like they meant to. Six names — --line, --muted, --fg, --fg-quiet, --bg-inset and --warn — were read across the sheet and defined nowhere, neither in CSS nor from the code. An unresolvable var() is invalid at computed-value time, which does not skip the declaration: the property takes its inherited value if it inherits and its initial value if it does not. So border: 1px solid var(--line) came out border-style: none and drew no border — on the colour ramp beside an annotation, on the share dialog’s link box, under the analysis drawer’s map tabs and round a plot control’s number box. background: var(--line) came out transparent, so the well behind a feature-count bar and the one-pixel divider in the plot controls were invisible. And color: var(--muted) inherited, so two labels meant to sit quietly under something else were drawn at full strength. Each of those looks, in a screenshot, exactly like a deliberate choice, which is why none was found.

    --warn is now a real token in both themes, and the three rules that wanted a warning colour stop inventing one each: .pairs-warning was written var(--warn, var(--accent)) and therefore drew a warning in link blue, and the other two hard-coded ambers that never changed in the dark theme. .input.is-bad takes --danger like the .input-region.is-bad three thousand lines above it, instead of a red of its own that stayed dark on the dark theme’s dark surface.

    test/unit/css-tokens.test.ts is why there is not a fourth time. It reads every var() in the sheet and fails, with the line number, on any name nothing defines — allowing only the sixteen properties the code writes with setProperty, and checking that allowance against the source so it cannot rot. It also holds the two halves of the dark palette to each other and the light palette to the dark one’s set of names, which is how --tab-rest came to exist in four of the six blocks that carried a palette and in neither of the other two.

  • The palette is written once. The light values were spelled out in full in four places — :root, [data-theme='light'], .content and .analysis-figure — and are now one selector list that names all four. Eighty-four declarations become sixteen, and the two boxes that stay light while the furniture goes dark can no longer drift from the theme they are a copy of. The dead var() fallbacks went with it: var(--accent, …) appeared with three different fallbacks for a token that is always defined, and fifteen font sizes bypassed the type scale for values that were a step under another name.

  • A bacterial GFF arrived as 87 features out of 5,870. A 6.4 Mb Pseudomonas aeruginosa PAK annotation — 5,783 CDS, 74 tRNA, 12 rRNA, one tmRNA — opened as 87 anonymous boxes: every RNA in the file and not one of its proteins, each drawn with no name and no accession. The count is the diagnosis. 74 + 12 + 1 = 87, so what came through was exactly the rows whose feature type ends in the letters rna.

    The parser only knew the hierarchy GTF and an Ensembl GFF3 are built from — gene, transcript, and the exons and CDS underneath — and it keyed every row that was not a gene or a transcript by its Parent, because in that world such a row is a fragment and the parent is the thing being drawn. A row naming no parent could not be placed, and was skipped. A bacterial annotation has no hierarchy in it at all: Prokka, Bakta and DFAST write one row per feature, each with its own ID and locus_tag and not one Parent anywhere in the file, because a bacterial gene is a single uninterrupted CDS and the gene and mRNA rows Ensembl writes would each be a second copy of the same span. So all 5,783 CDS rows went looking for a transcript they had never named and were dropped, while the tRNAs and rRNAs matched the “is this a transcript” test on their type and came through on their own IDs. That the survivors were a plausible-looking 87 features rather than an error is why this read as a file that had loaded.

    A row that names no parent is now read as the whole feature it is. It is keyed on its own ID — so two rows sharing one, which is GFF3’s way of writing a feature with a gap in it, are one glyph — and a row carrying no ID at all is drawn keyless rather than collected with every other such row into one feature stretching across the file. Where a file does say what a row belongs to, that still decides and nothing changes: a CDS with a Parent still folds into its transcript and is not drawn beside it.

    Three things that were being thrown away come with it, because 5,870 nameless boxes is not much better than 87. locus_tag now counts as an accession — it is assigned per gene by definition, and it is the only one a Prokka file writes — so the 2,643 hypothetical protein rows that carry no symbol are labelled IMMMIJEE_00005 instead of nothing, and the search box can find them. A bare gene attribute now counts as a symbol, which is how NCBI and Prokka both spell one, so dnaA, gyrB and 3,139 others are drawn under their own names. And product joins biotype and source in the detail string: it is the whole of what a bacterial annotation has to say, the feature card had been showing source Prodigal:002006 and stopping, and the colour picker (§8.16) can only offer a column that is written there.

    One row type had to be turned away deliberately as a result. NCBI opens every contig with a region spanning it end to end, and a GFF converted from GenBank writes source for the same thing; both name no parent, so both used to fall off the same end the CDS rows did. Drawn, each would be a box the width of the chromosome sitting on top of the genes.

  • A species with no README.json no longer fails the whole Stores run. --readme optional is the default precisely because those files are hand-maintained across hundreds of species, and it promises that a species without one keeps every file it has and loses two columns. Against recorded fixtures it did exactly that; against the bucket it could not, and the first weekly run of the DNA Zoo store died on Preliminary/ — a top-level directory that is not a species and never had a README. Nothing was published that week, so the shelves readers saw stayed as they were.

    The cause is one fetcher doing two jobs. A portal search is read by a function that treats 404 as zero results only when the body is JSON — 4DN’s way of saying a facet matched nothing — and turns every other status into the end of the run. A bucket refuses a key that is not there with a 404 and an XML body, which landed in that function’s “the endpoint has moved” case. Reading a document that may simply be absent is now its own function, and it answers no document to any status and to a body that is not a JSON object. Absence and outage are still told apart: a host that cannot be reached, or that stops talking part-way through three times over, still ends the run, because a store is only ever replaced by a run that succeeded. --readme require still fails on the first missing one, which is what it is for.

    A run where no directory yielded a README now says so in a line of its own. Every row is still published and the run still succeeds — but a bucket that answered for its objects and for none of its READMEs has more likely been rearranged than lost every one at once, and two silently empty columns are not a thing to find out about from the shelf.

    • insulation hit the 2 GiB limit on a single Float32Array, which is a limit of the tab and not of the machine. That is 23,170 bins: 116 Mb at 5 kb, so mouse chr9 was refused and chr1 could not be run below 10 kb.
    • loop calling never reached the allocator. A hard-coded 8,192-bin cap skipped any longer sequence, which is 82 Mb at 10 kb and 41 Mb at 5 — so mouse chr18 was dropped at 10 kb and every mouse chromosome at 5 kb.

    Insulation now walks each sequence as overlapping squares with a halo the width of the widest diamond. The split that makes this a substitution rather than an approximation is between the sums, which are local to a bin, and the score, which is a log2 ratio against the mean over the whole sequence: each tile files the sums for the bins whose whole diamond it holds, and the score is taken once at the end. diamondSums is untouched and still goldened against cooltools; the answer is identical cell for cell, not close. Mouse chr1 at 1 kb — 195,471 bins, which is 153 GB as a square — now runs in 19 seconds inside a 4 GB heap.

    Loop calling reads the band it was always going to scan. chromosight.ts had already banded every one of its own objects, saying so in as many words; the square read was the last n² thing in the module and the gate was the fence built around it. The gate is now a bound on the band — the scan distance times the sequence — so it scales with the setting that actually costs: the whole mouse genome scans at 5 kb, and what is still refused is a deep scan on a fine grid, refused by name with the two settings that fix it. Mouse chr1 at 5 kb, a 6.1 GB square, takes 68 seconds.

    One thing genuinely needed the square and now comes from the pixel table instead: the detectability cut counts non-zero pixels per bin over a whole row, at every separation. It is counted once per run and only where the file carries no balancing weights — with them nothing is read for it at all.

  • A sequence a scan skips is named. The cap’s own documentation has always said a sequence past it is “skipped and named”; only the first half was true, so a run over a mammalian genome scanned whichever chromosomes happened to fit and reported a clean number for the rest. Worse, the message when nothing fitted said the sequences were not long enough, when the truth was the opposite.

  • metacooler-run --sequences binds. The runners read that parameter with Array.isArray and fall back to every sequence for anything else; the shell passed a plain string, so --sequences chr18 silently scanned all of them and reported a number from the wrong one. Affected loop calling and compartments.

  • The domain pileup — APA over a set of TADs, scaled — was laid out from the wrong end of the feature. The scaled mode on a feature set is how you draw the picture that sits beside a loop APA in every Hi-C paper: call insulation boundaries, take the span from one to the next as a domain, and pile every domain up stretched to the same width with padding either side. It read the window as [midpoint − flank, midpoint + length + flank] — the right width, and half a domain to the right of where it belongs — so the body sat against the top-left corner of the picture with the whole flank on the far side. The window is now [start − flank, end + flank] on both axes, which puts the domain in the middle and its two boundaries on the cross through it.

    Nothing in the old figure said it was wrong, which is what makes this worth a paragraph rather than a line: a shifted domain pileup is still a square with bright and dark blocks in it, and the only way to catch it was to know where the corner peak should have been.

  • Every domain’s boundary now lands on the same grid line. A scaled window used to be stretched evenly onto the grid, so a 20 kb domain’s edge fell on one column and a 200 kb domain’s on another — averaging them softened both boundaries into a couple of columns of gradient, which in an aggregate looks exactly like a real boundary that is soft. The grid is now explicitly flank, body, flank: the body’s two ends are pinned to their own columns for every domain whatever its length, and the flank each side is a fraction of that domain rather than a rounded number of bins.

  • A distance-matched control is shifted by a multiple of the window when the window is a scaled one. Asked for in base pairs — the old control, and its 100 kb floor — a control for a megabase-wide domain window was ninety per cent the same cells as the thing it was the denominator of, so the ratio came out at 1 everywhere and the domain washed out of the picture with nothing on screen to say why. The fixed mode still asks in base pairs, which is the right unit for a window a couple of dozen bins wide.

  • A scaled window off the diagonal — a loop pileup whose window scales with the separation — is now symmetric about its anchor bin rather than a bin short on one side of it.

  • metacooler-run takes the ::/resolutions/<n> address its own refusal tells you to write. An .mcool is a collection of coolers, and opening one at its root is refused with a sentence naming the resolutions and an example ending in ::/resolutions/25000 — advice the shell could not then take, because the whole string went to stat and there is no such file. So there was no way into an .mcool from a command line at all. The :: half is now split off for the filesystem and kept for the container, which is where the group is read from. Outputs are named sample_25000.… rather than 1000.…, which is what basename of a group path had been giving them.

  • The tick labels on a matrix output that are positions on a continuous axis rather than one-per-cell names no longer land over the first few columns of the exported TSV. They go in a # line saying what they are, and the columns keep their indices.

  • A contact map is never put on a track shelf. A hub’s type hic track has a row of its own that opens through the map door, and it was also going onto the genome row’s shelf — so open with its tracks handed it to the annotation loader, which read the binary as text, sniffed it as a BED and reported that all 32,918 of its lines failed the contig/start/end test. A true sentence about the wrong question. A shelf is annotations, a contact map is not one, and the row that opens it as a map was there all along.

  • “Open with its tracks” loads them. It opened the file and offered the tracks behind a button, which is the thing a reader who pressed those words had just pressed past. The heading verb now has a road of its own through the shell (openWithTracks) that marks the shelf as asked for, and a session with an asked-for shelf loads it instead of drawing the offer. Every other road to the same file — a row’s own open verb, a ?store= link, a dropped copy — keeps the offer, because opening a genome is not a request for eight more files. The mark is spent when it is read, so closing the tracks and reopening the same genome does not bring them all back.

  • The tracks published beside a genome are offered in the 1D browser. The map path has offered its shelf since the demo map shipped with ten annotation files — one click, and a reader who brought no tracks has a picture — and the browser path never did. Nothing had noticed, because until now the only thing that registered a shelf was a store row whose file was a contact map.

    A track hub makes it the common case and makes it visible: an assembly hub’s genome is its .2bit and its whole trackDb is the shelf that rides along, so open with its tracks on a hub’s assembly heading opened the genome and dropped every track on the way. An IGV genome row carries the same shelf and was losing it the same way. The Tracks card now offers them in a browser session exactly as it does beside a map, through the same one question and the same gate — so a restored session, which is bringing its own tracks back, is still not offered them on top.

  • A 4DN .hic drew a blank map as balanced at 1 kb and 2 kb. Juicer writes a KR entry for every chromosome whether or not the balancer converged, and where it did not the vector behind the entry is all NaN — the chicken maps carry one at 1 kb and 2 kb for every chromosome, beside a VC_SQRT and a VC that are whole. The reader chose its normalisation by name alone, per file, and never looked behind it, so every cell multiplied by NaN and the legend read 0 to 1. A chromosome whose preferred vector has no finite value in it now takes the next normalisation down the preference list (hic/HicFile.ts, normVector), and normTypeFor says which one it got.

  • Reading a single-cell container in small pieces looked hung. The listing is a thousand synchronous range requests inside one h5wasm call, so the bar said listing cells… and nothing else for as long as it took — minutes on a slow link — and the open then went on to probe one dataset header per cell for a pixel count nobody was waiting for, another four thousand round trips. The requests now count themselves out loud (listing cells · 512 reads — 8.0 MB), and the per-cell count is skipped on that source: unknown is what it is, and the File card says so.

  • A file that is not HDF5 failed as error - name not defined!. An HTML page saved under a .mcool name, a download that stopped short, a text matrix: h5wasm found no superblock and said so in its own words, which reached the screen as something went wrong. The container is now refused by its first bytes, in a sentence that names the file, and a failure h5wasm raises on a file that is HDF5 is said about that file and group rather than about nothing.

  • A contact map on Google Drive was downloaded whole. A browser tells every host it accepts gzip, and Drive takes it up on an unranged HEAD: Content-Encoding: gzip, chunked, no length. The map door read that as a host that re-encodes what it serves — GitHub Pages does, and ranges through a gzip stream are garbage — and took the fallback for such a host, one GET of the whole file into memory, silently and whatever the size: 81 MB for the .mcool this was found on, and the same road for a 2 GB one. Drive answers every ranged request raw, so a HEAD that comes back re-encoded is now followed by one more, for Range: bytes=0-, and a 206 that is not re-encoded and states its length is read by range from there — the file’s length, since the range is all of it. Pages re-encodes that too and is refused exactly as before, one request later (docs/hosting.md, docs/remote-sources.md).

  • A file picked from Google Drive took a long time to open, under a name that was its id. A Drive file is addressed by an id, so nothing in its address says what it is, and the session took the contact-map door first: a HEAD, then HDF5 hunting for a superblock at doubling offsets — a megabyte chunk at each — through the whole of a bigWig, before the track door read the file’s header three times over, four small requests each. Over the Drive API, where a request is the better part of a second, a 56 MB bigWig sat at Opening 1pq7NDWo…?alt=media… for most of a minute. The name a folder gives a file now decides the door where its address cannot, a bare address is asked what it is before the map door is tried, and the annotations worker reads a remote file in 256 KiB chunks it keeps, one handle per address — so the same open is three requests and 0.6 MB, and the loading screen and the tab say ATAC_rep2_WBcel235.bw (SPECS §24.9). A presigned URL’s tab loses its signature the same way: a query string is the request, not the name.

  • Opening a 4DN BAM as a genome fetched the whole file. 4DN’s open-data bucket exposes ETag and nothing else to a page, so the browser could not see the Content-Range the file handle reads a size off, and the handle reported nought bytes. The bounded header read was then a read of nought bytes, “not a BAM”, and the alignment file was fetched whole — gigabytes, behind Reading 4DNFIV9TCZVO.bam — to find out what its first block said. A size the handle cannot give is now asked for with a HEAD, whose Content-Length every page may read; a size nothing states is unknown rather than empty and the header is still read within its bound; and the browser opens from the header in three small requests, with the index’s download drawn as a bar on the row while it is already on screen (SPECS §8.8).

  • A merged pull request’s preview stayed in the About dialog’s version picker. Merging fires pull_request: closed — the run that deletes the preview — and push to main in the same instant, and both land in the pages concurrency group; GitHub keeps only the newest pending run in a group, so whenever something was already deploying, the removal was cancelled about a second after it queued and the review copy outlived its review. #49 and #50 were both lost that way, behind a deploy the Stores workflow had dispatched a minute earlier.

    The deploy now reconciles rather than trusting the event: before publishing, it asks GitHub about every preview in the manifest and drops the ones whose pull request is no longer open. That also covers a removal that failed outright, and one whose pull request closed while the workflow was broken. A pull request the API will not answer for is left alone — I could not ask must not read as it closed.

  • The 4DN shelf could not be generated at all. Its first live run died on IncompleteRead(43378383 bytes read, 39983032 more expected): the widened query asks the portal for every experiment set with all four of its file arrays embedded, which is an 83 MB response, and the socket closed half way through it — as a Python traceback, where every other failure in make_store.py is a sentence saying what to do. IGV and ENCODE published fine; nothing was published, because a run that loses one front end publishes none of them (the branch is replaced wholesale, so a missing store would delete last week’s good copy of that shelf).

    4DN’s search is now paged — 50 records a request, each retried on its own — and ENCODE’s is deliberately not, which the next run proved the hard way: paged uniformly, ENCODE answered &limit=500&from=0 with 403 Forbidden, having answered the same query with limit=all perfectly the week before. The two portals want opposite things of one search, both answers are measured, and --page-size is there for the run that disagrees. A 403 on a page now names --page-size 0 in its own message, since that is the fix and no status page will suggest it.

    Around that: every whole read is retried three times when a host agrees to answer and then stops talking. An HTTP status is still never retried, since 4DN answers a search matching nothing with a JSON-bodied 404 and retrying that would turn zero results into a failure. The paged walk stops on the portal’s total, on a short page, or on a page that repeats what it has already sent — and that last one fails the run when it happens early, because a portal ignoring from would otherwise publish a catalogue that draws with empty cells in nine rows out of ten.

    The suite drove the generator only through recorded responses, which is how this shipped: the recorded path reads a file and the live path walks a portal. --portal-base now points a front end at a portal served by the test itself — out of process, since spawnSync blocks the one running the assertions — and the five ways a walk ends are each made to happen, including the cut off response that started this.

Removed

Section titled “Removed”

  • The header’s plug and +. Connect a place and Add a file to this tab stood in the header beside the store drawer’s toggle and were the Files column’s own Open a local/remote folder and the file crumb’s Open a file said a second time, one row up; a header with three doors to a file read as three different things. Both verbs stay in the command palette, and dropping a file still adds it. The hints that pointed at “the plug in the header” now point at the Files column.

  • The Buckets card, the bucket browser and the shelves dropdown. The plug’s Buckets card listed what the Files panel already lists and edited keys the provider pane now edits; the browse bucket… dialog behind four URL boxes browsed buckets and nothing else, where the window can be connected to a folder, a Drive or a Dropbox too; and the eighteen-entry dropdown of shelves, the landing page’s URL box and its private buckets… button were the store tiles, the Load box and the plug under other names. The two 4DN maps that sat in the Demos store are on 4DN’s own page, where every 4DN map is. Earlier unreleased builds called a store a hub (metacooler.hub, ?hub=, make_hub.py, the hubs branch); none of those names is read any more.

  • The log₂ ratio combine operation. It was a scale wearing an operation’s clothes: it put the same finding in two rows and left only one of them exportable as the quantity it measured — a bigWig of log₂ ratios is a file of a picture, and anything downstream that wanted the ratio had to undo it. The reason it existed is real and is answered above, on the lane’s own axis. Two operations remain, a ratio and a difference, and either can be drawn as a logarithm.

  • The Domains (CIDs) task, which was withheld from the panel on every file and is now redundant. Everything it did is reachable and in one place: insulation calls the boundaries, calls the domains between them, and an APA over those domains is the pileup. What it added over that was a composite whose three settings never reached the step they named — AnalysisRunner.plan walks a required task at that task’s defaults — so its window, its region and its prominence changed nothing, and its estimate read a window labelled base pairs as a count of bins. A task nobody could run, whose settings did not work, duplicating two that do.

  • Diamond insulation calls the domains between its boundaries, and does it by default. A second overlay beside the calls: the span from each boundary to the next, drawn as a segmentation the way the A/B compartment track is, and exportable as BED like any other called interval set. A boundary set is half an answer — everything downstream of insulation takes an interval rather than a point, and the scaled pileup over these is the domain APA — so what every reader was doing by hand (sort per sequence, pair the neighbours) is now a tickbox, and it is ticked.

    Three decisions in it. Consecutive domains tile: one ends where the next begins, so the lane reads as a segmentation rather than as boxes with gaps, and a domain’s two corners sit on the bins the calls were actually made at, which is what a scaled pileup lines up on. Each carries the weaker of its two edges as its score, because a domain is only as well defined as its worse-supported side and reporting the stronger would let one good boundary vouch for a run of bad ones. And two boundaries make a domain, one makes nothing: the two ends of every sequence are left out rather than run to the telomere, which would assert an edge the data never placed.

    On the yeast demo: 710 boundaries across 16 sequences, and 694 domains — one fewer per sequence, which is what the arithmetic says it should be.

  • metacooler-run writes a called interval set as BED beside its TSV, the way it already wrote bedGraph and bigWig beside a profile’s. The drawer has carried a BED button since there were called intervals at all; a batch run got a TSV with a provenance header, which is readable and is not what bedtools takes.
