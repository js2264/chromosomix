## Reporting a problem

Open an issue on [GitHub](https://github.com/js2264/chromosomix/issues). Say what you did, what you
expected and what happened instead, and which build you were using: **About → version** names it
exactly, and so does the `/Producer` field of any PDF the app exports. If a file will not open, say
where it is hosted and what kind of file it is; a link that opens the view you were looking at is the
fastest way to show it (see [Sessions, workspaces and links](/browse/sessions-and-links/)). A link to a
file on your own disk cannot travel: describe the file instead.

## What is where

| In the repository | What it is |
| --- | --- |
| `src/` | the app, in TypeScript: readers, rendering, the views, the analyses, the command line |
| `SPECS.md` | the contract: what the app does and why, section by section |
| `CHANGELOG.md` | what changed in each release |
| `GLOSSARY.md` | the words the code uses in a sense of its own |
| `test/` | the test suite, with the oracle files the analyses are compared against |
| `notebooks/` | the validation, timing, parity and laptop notebooks ([How the results are checked](/analyses/validation/)) |
| `widgets/` | the Jupyter and R packages |
| `electron/` | the desktop app's shell |
| `documentation/` | these pages |

`SPECS.md` comes first: a change to what the app does changes the section that governs it, and the
changelog's *Unreleased* list, in the same pull request.

## Building and testing it

You need Node 22.12 or later.

```sh
git clone https://github.com/js2264/chromosomix
cd chromosomix
npm install
npm run dev            # the web app at http://localhost:5173
npm run test:nofixtures   # the tests that need no generated fixtures
npm run build:cli && npm link   # the chromosomix command, from your clone
```

The rest of the suite reads fixtures generated by Python scripts (`npm run fixtures`); the repository's
continuous integration runs every part a runner can build.

## Improving these pages

Every page has an **Edit page** link at its foot, which opens its source on GitHub. The guides are
written by hand in `documentation/src/content/docs/`; each task's parameters, the reference pages and
the release notes are written from the app's own code each time the site is built, so a change to
those is a change to the app. `documentation/README.md` says how the site is built, how its versions
work, and how a page is written: who it is for, how it is checked, and the few rules of its format.
The site needs Node 22.23.4 or later.

```sh
npm ci --prefix documentation
npm run docs:dev       # the site at http://localhost:4321
npm run docs:build     # every internal link checked
```
